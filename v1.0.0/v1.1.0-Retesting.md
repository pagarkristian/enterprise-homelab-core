## 1. What This Confirms

Each vulnerability from [v1.0.0-vulnerable.md](./v1.0.0-vulnerable.md) was re-attacked, from the same Auditor Node (`10.216.27.10`), after the hardening in [v1.1.0-hardened.md](./v1.1.0-hardened.md) was applied. The full attack-by-attack walkthrough, with every command and screenshot, lives in the counterpart repository — see [redteam-homelab-toolkit: v1.0.0 audit report, Retesting section](https://github.com/pagarkristian/redteam-homelab-toolkit/blob/main/v1.0.0/v1.0.0-audit_report.md). This document summarizes the result from the defender's side.

A quick recon pass confirmed the surface-level changes took effect before the re-attacks were run:

```bash
nmap -p- -sC -sV -A 10.216.27.100
```

## 2. Result Summary

| Vulnerability | Fix Applied | Re-attack Result |
|---|---|---|
| SQL injection (auth bypass) | Prepared statements, bound parameters | `admin'#` payload no longer bypasses the login — input is treated as a literal string, not SQL syntax. Access denied. |
| Unrestricted file upload (RCE) | Extension whitelist + `.htaccess` script-execution block | Uploading `exploit.php` is rejected outright ("Gagal! Format file tidak diizinkan") before it ever reaches the filesystem. |
| SSH brute force | Key-only auth, non-standard port, Fail2Ban | Hydra's dictionary attempt against port 2222 triggers Fail2Ban, which bans the attacker's IP after the configured threshold of failed attempts. |
| Anonymous FTP access | `anonymous_enable=NO` | Anonymous login attempt is rejected with `530 Login incorrect`. |
| MikroTik perimeter | NAT + filter rules restricting WAN input | Unsolicited inbound traffic from the WAN-facing interface is dropped at the gateway. |

**Not retested in this cycle:** the unauthenticated Samba share identified in v1.0.0 — see the open item noted in [v1.1.0-hardened.md](./v1.1.0-hardened.md).

---

## 3. Conclusion

Every attack path that worked against the v1.0.0 baseline failed against the hardened v1.1.0 server, across all three layers that were changed: network perimeter (MikroTik), host/service configuration (SSH, FTP, Fail2Ban), and application code (prepared statements, upload validation). This closes the v1.0.0 → v1.1.0 cycle; v2.0.0 picks up from this hardened baseline and adds new business features — deliberately, with new mistakes — to test the next stage: SIEM detection.
