# 🏛️ v1.0.0: Vulnerable Baseline

This document covers the network build-out and the server configuration for the v1.0.0 lab — a small-business-style network with several real, common misconfigurations left in on purpose, so they could be attacked and then fixed one at a time.

---

## 1. Network Topology & Asset Inventory

The lab runs in an isolated internal segment (`10.216.27.0/24`), with no direct exposure to the internet, to keep testing safe.

### IP Address Allocation

| Host | Role | OS | IP Address | Open Ports |
| :--- | :--- | :--- | :--- | :--- |
| **Core-Gateway** | Edge router / NAT | MikroTik RouterOS v7.21.4 | `10.216.27.1` | 8291 (Winbox) |
| **TechSecure-Portal** | Web target | Ubuntu Server 24.04 LTS | `10.216.27.100` | 80 (HTTP), 21 (FTP), 139/445 (Samba) |
| **Auditor-Node** | Attacker | Kali Linux | `10.216.27.10` | Dynamic / outbound only |

### Network Adapters

Every VM (MikroTik, Ubuntu, Kali) uses 2 network adapters:
- **Adapter 1 (NAT):** gives the VMs internet access for updates/packages.
- **Adapter 2 (Host-Only):** gives each VM a private LAN IP so they can reach each other inside the lab.

## MikroTik Configuration

The MikroTik gateway needs to forward LAN traffic to the internet:
- **Chain:** `srcnat`
- **Action:** `masquerade`
- Translates private LAN IPs to the router's single public-facing IP so LAN devices can reach the WAN.

`IP > Firewall > NAT > +`

## 3. Service Logic & Vulnerability Deployment

### FTP: Anonymous Access Left Enabled

FTP is an old file-transfer protocol that's frequently misconfigured to allow passwordless (anonymous) login. In this baseline, that misconfiguration is left on purpose.

```bash
sudo nano /etc/vsftpd.conf
```

<img width="823" height="400" alt="Screenshot 2026-05-18 145159" src="https://github.com/user-attachments/assets/69aa6b87-9b47-439f-921d-63c9810d43ae" />

```bash
sudo chmod 655 /etc/vsftpd.conf         # Grant standard read-write permissions to the config file
sudo systemctl restart vsftpd           # Apply the config change

sudo mkdir -p /var/ftp/pub              # Public folder — this is where the leaked credential file goes
sudo chown -R nobody:nogroup /var/ftp   # Keep ownership at the unprivileged FTP guest account
sudo chmod 755 /var/ftp                 # Normal traversal permissions

sudo nano /var/ftp/pub/admin.txt        # Plant a plaintext credential file here (the thing the anonymous login exposes)
sudo systemctl restart vsftpd
```

### CTF-Style Flags

To make verification of full compromise concrete (similar to a Hack The Box-style flag), flag files are planted at two different privilege levels on the target.

```bash
# Low-privilege flag (reachable via the anonymous FTP share)
echo "UTM{ftp_anonymous_data_exposure_9f27d8}" | sudo tee /var/ftp/pub/user.txt
```

```bash
# Root-level flag (reachable only after full privilege escalation)
sudo echo "UTM{root_ssh_privilege_escalation_b623cf}" | sudo tee /root/root.txt
chmod 600 /root/root.txt
```

## 5. How These Flaws Chain Together

How an attacker could combine these weaknesses to fully compromise the server:

1. **Anonymous FTP access** — log in with the default anonymous account (no password) and browse `/var/ftp/pub/`. Downloading `admin.txt` leaks plaintext credentials/notes.
2. **Unauthenticated Samba share** — the public share has no access control, letting anyone read/write files on it and map out internal file layout.
3. **SQL injection on `index.php`** — because input isn't sanitized or parameterized, a boolean payload like `' OR '1'='1` bypasses the login entirely, without a valid username or password.
4. **Unrestricted file upload on `dashboard.php`** — once inside the admin panel, the upload has no extension filter. Uploading a PHP web shell and then browsing directly to it in `uploads/` gives arbitrary command execution on the server.

The full exploitation walkthrough for each of these — actually running the attacks and capturing the flags — is documented in the counterpart repository: [redteam-homelab-toolkit, v1.0.0](https://github.com/pagarkristian/redteam-homelab-toolkit/tree/main/v1.0.0).
